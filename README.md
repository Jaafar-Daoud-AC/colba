## 📖 نبذة عن المشروع

**كولبا** تطبيق لإدارة المحلات والمخازن: مخزون، فواتير استلام، جرد، مصاريف، صندوق نقدي، وإحصاءات وتحليلات، ضمن واجهة عربية (RTL) مصمّمة للموبايل أولًا، ويمكن تثبيتها على الهاتف كتطبيق (PWA).

> ✅ **تم تصميم هذا التطبيق لعمل خاص، وجُرّب فعليًا في الميدان وبأداء ممتاز، ويصلح لإدارة المخازن والمحلات المتوسطة والصغيرة.**

والفكرة التي يقوم عليها: **لا يوجد تعديل يدوي للكميات ولا للبيع.** كل زيادة في المخزون تمر عبر فاتورة، وكل عملية بيع تُستنتج من فروق الجرد، وكل سحب من الصندوق يتطلب سببًا مكتوبًا، فيبقى لكل رقم أثر موثّق.

## ✨ المميزات

### الشاشات الرئيسية

| الشاشة | ما تقدّمه |
|--------|-----------|
| 🏠 **الرئيسية** | رأس المال، المردود الكلي والفعلي، التكاليف والضرائب وأجور العمال، رصيد الصندوق، والفائض/العجز النقدي |
| 📦 **المنتجات** | قائمة غير محدودة العدد، تصنيف بالفئات، إضافة وتعديل وحذف، وإنشاء فاتورة لكل منتج |
| 📊 **الإحصاء** | الإحصاء اليومي، إغلاق اليوم، وسجل الجرد النقدي |
| 📝 **الجرد** | جلسات جرد (بداية/نهاية) والفرق يُسجَّل كمبيع تلقائيًا |
| 📈 **التحليلات** | رسوم زمنية، الأكثر مبيعًا، أعلى وأقل كمية بيعت، وتغيّر أسعار الشراء والبيع |

### المنطق المحاسبي

- 🧾 **دورة مخزون بالفواتير:** لا تُعدَّل الكمية يدويًا، وكل فاتورة تُحفظ في سجل دائم قابل للفرز (بالتاريخ أو التكلفة أو الكمية).
- 🔄 **إعادة التقييم:** عند وصول فاتورة بسعر شراء مختلف، يُحسب أثر الفرق على الكمية القديمة تلقائيًا كربح أو خسارة ويُحفظ في سجل مستقل.
- 💸 **مصاريف يومية موثّقة:** لكل مصروف فئة وسبب، ويُخصم تلقائيًا من الصندوق.
- 💰 **جرد نقدي:** تُدخل المبلغ الحقيقي في الصندوق فيقارنه النظام بالمتوقع ويحفظ الفائض أو العجز تاريخيًا.
- 🔐 **سحب الصندوق بملاحظة إلزامية:** لا سحب بدون سبب.
- 🧮 **الحسابات في الخادم:** كل الأرقام تُحسب من البيانات الفعلية في قاعدة البيانات.

### التجربة والتقنية

- 📱 **تطبيق قابل للتثبيت (PWA)** على أندرويد بدون متجر.
- 🌙 **واجهة عربية RTL** بخط Tajawal، متجاوبة بالكامل.
- ⚡ **Service Worker** لتسريع التحميل وعمل جزئي بدون اتصال.
- 🩺 **نقطة فحص صحة** على `/api/health`.
- 🗄️ **SQLite محليًا وPostgreSQL في الإنتاج** بالتبديل التلقائي عبر `DATABASE_URL`.

## 🛠️ التقنيات المستخدمة

| الطبقة | التقنية |
|--------|---------|

## 🚀 التشغيل محليًا

```bash
git clone https://github.com/Jaafar-Daoud-AC/colba.git
cd colba
pip install -r requirements.txt
python3 app.py
```

يفتح على `http://localhost:5000`، وتُنشأ قاعدة SQLite محلية تلقائيًا (`colba.db`) ولا تُرفع إلى Git.

### استخدام PostgreSQL / Supabase

عيّن متغير البيئة `DATABASE_URL` برابط الاتصال قبل التشغيل، وسيكتشفه البرنامج تلقائيًا:

```bash
export DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DBNAME"
python3 app.py
```

> 🔒 **لا ترفع رابط الاتصال أبدًا إلى GitHub** لأنه يحتوي كلمة مرور قاعدة البيانات. ضعه في متغيرات البيئة فقط (محليًا أو في لوحة Render).

## ☁️ النشر على Render

1. ارفع المشروع إلى مستودع GitHub.
2. من [render.com](https://render.com) اختر **New ← Web Service** واربطه بالمستودع (الفرع `main`).
3. سيقرأ Render الملف `render.yaml` تلقائيًا:
   - **Build:** `pip install -r requirements.txt`
   - **Start:** `gunicorn app:app --bind 0.0.0.0:$PORT`
4. أضف `DATABASE_URL` في **Environment** برابط قاعدة بياناتك.

| الإصدار | المنصة | أبرز ما فيه |
|---------|--------|-------------|
| `v0.1.3` ← `v0.1.6` | سطح المكتب (Tkinter + SQLite) | الأساسيات: جداول المنتجات، الإضافة والتعديل والحذف، المجاميع، شاشة يومية وجرد |
| `v0.1.7` | سطح المكتب | إعادة تنظيم الكود بدوال مساعدة، ورسوم بيانية بـ matplotlib |

## 🎓 ماذا تعلّمت من هذا المشروع؟

- بناء **REST API** كامل بـ Flask وتصميم نماذج البيانات بـ SQLAlchemy.
- الانتقال من **ملفات نصية** إلى **SQLite** ثم إلى **PostgreSQL**.
- فروق SQLite وPostgreSQL العملية (مثل صرامة مقارنة التواريخ) واستخدام مشغّل **psycopg 3**.
- تحويل برنامج سطح مكتب إلى **تطبيق ويب متجاوب** بدون أي إطار عمل.
- بناء **PWA**: الـ Manifest والـ Service Worker وإدارة إصدارات الكاش.
- تصميم **منطق محاسبي** موثّق الأثر: فواتير، إعادة تقييم، جرد، وفائض/عجز.
- النشر على **Render** وإدارة متغيرات البيئة وحماية الأسرار.
- إدارة **الإصدارات** عبر Git وSemantic Versioning وGitHub Releases.
